# 通用协作与每日管理（1.2.0）

## 架构

继续使用原有 Next.js、SQLite、网站密钥和 `/api/agent/v1`；无第二个密钥系统、独立任务数据库或后台模型调用。每个 AI 独立密钥对应执行者身份，专业角色由任务 action 决定。执行者数量不设固定上限，实际吞吐由单服务器资源决定。

`analysis.work` 与 `analysis.energy` 可并行；`daily.plan` 等待前两者；用户确认后可创建 `feishu.publish`；反馈进入 `daily.review`；最近七天结果进入后续规划上下文。

已有 worker 密钥按用户明确授权兼容业务读写；新账号使用 write 密钥。read 密钥仍不能修改数据、登记执行者或领取任务。密钥/账户管理与自动设置使用登录会话。原记录 API 的乐观版本控制继续有效。

## 队列保障

- SQLite BEGIN IMMEDIATE 事务实现独占领取；同一密钥受 max_parallel 限制。
- 任务能力必须在执行者登记能力中，未登记客户端只能执行定向模拟任务。
- 租约 120 秒，建议每 30 秒心跳。相同成功结果重复提交幂等。
- 纯分析任务超时最多三次尝试；外部操作超时、失败或部分完成进入 needs_review。
- 每日数据变化时旧分析不能覆盖新版本；依赖结果由服务端带入领取响应。
- 飞书回执必须覆盖所有事项。执行者必须使用 job_id/item.id 查重；服务器无法独自确认飞书操作是否真正发生，不宣称跨服务 exactly-once。
- 暂停执行者禁止新领取，已经领取的任务可完成；撤销密钥则所有请求失效。
- API 返回最近 100 条任务，数据库保留完整记录和审计。需要更长历史时可扩展分页。

## 调度

Compose scheduler 每 30 秒维护任务租约、生成到点的规划和复盘，与应用共享同一个数据卷。首次部署自动开关默认关闭，用户在网站设置北京时间与飞书开关。每日期每类当前数据版本只生成一次；输入或反馈变化后重新安排过期分析，重启不重复补发；停机后只补当天，不补历史天。复盘需要已确认计划。

AI 自身仍需在自己的运行环境设置定时领取。服务器不能启动外部消费级 AI 账号。没有在线执行者时状态为等待。任务失败可在网站查看原因和核对后重试；未产生外部效果的流程可取消并重新生成。

## 接入与验收

以 public/ai-guide.md 为最新协议，部署到站点 /ai-guide.md。静态 Caddy 托管路径必须同步更新。

自动化测试覆盖多进程 SQLite 竞争、一个执行者串行完成角色、多身份并行、能力匹配、回传幂等、迁移、持久化、版本冲突、租约接替、外部效果保护、定时去重，以及真实 HTTP 权限和日计划流程。自动化执行者使用测试输出，不是实际 AI 质量验证。

真实验收：一个现有豆包账号登记后完成当天草案；用户检查草案并确认，记录反馈后执行复盘。具有飞书能力的 AI 执行发布后，用户在飞书核对真实结果。其他平台与多真实账号后续可沿相同协议验收，不要求为本轮测试新增账号。

## 当前边界

- 输出每日事项顺序、预计分钟、机动时间、暂缓理由；不做分钟级日历排班。
- 第一版健康分析只使用既有记录、自评、个人约束；未提供完整医疗、营养或训练处方系统。
- 网站是本轮数据依据，飞书端修改和完成状态不自动回流。
- 已成功发布飞书的计划不能自动撤回改版，以免重复生成待办；继续记录反馈即可。
- 数据结构校验只能保证格式和预算等约束，不能保证 AI 建议质量；草案需用户确认。
